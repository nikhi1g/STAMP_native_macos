# STAMP for macOS (Apple Silicon)

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23754637.svg)](https://doi.org/10.5281/zenodo.23754637)

A native macOS port of **STAMP 2.1.3** (Statistical Analysis of Metagenomic Profiles; Parks,
Tyson, Hugenholtz and Beiko, *Bioinformatics* 2014) for Apple Silicon Macs. It replaces the
Windows `STAMP.exe` run through Porting Kit/Wine or a virtual machine. The statistics, plots,
windows and menus are upstream STAMP's; only the runtime underneath them was ported.

- Upstream: <https://github.com/donovan-h-parks/STAMP> at commit `088aacd` (GPL-3.0)
- Requirements: Apple Silicon (M1 or later), macOS 12 or later
- Install: download the zip, open STAMP, click **Move to Applications**. Updates are offered
  inside the app. Details in [INSTALL.md](INSTALL.md).

## Stack

| Layer | Upstream 2.1.3 (Windows build) | This port |
|---|---|---|
| Language | Python 2.7 | Python 3.12 |
| GUI toolkit | PyQt4 (Qt 4) | PyQt6 (Qt 6.11), classic `Windows` style, in-window menu bar |
| UI definitions | 34 Qt Designer `.ui` files | the same files, regenerated with `pyuic6` |
| Plotting | matplotlib 1.4, Qt4Agg | matplotlib 3.11, QtAgg, with the 1.4 visual defaults restored per plot |
| Numerics | numpy, scipy 0.x | numpy 2.x, scipy 1.18 |
| BIOM import | biom-format 2.0 | biom-format 2.1 (dialog adapted to the current API) |
| Packaging | py2exe + installer | PyInstaller `.app` (arm64), zip / dmg / pkg |
| Distribution | unsigned `.exe` | Developer ID signed (hardened runtime), Apple-notarized, stapled |
| Updates | none | Sparkle 2.10, EdDSA-signed appcast |

Dependencies are locked with `uv` (`pyproject.toml`, `uv.lock`).

## Application architecture

**Core (unchanged in behaviour).** STAMP loads a tab-separated profile (hierarchical features ×
samples) and a metadata table into `metagenomics/` profile objects (`SampleProfile`,
`GroupProfile`, `MultiGroupProfile`). Three analysis modes (two samples, two groups, multiple
groups) are populated at start-up by `plugins/PluginManager`, which imports every module in a
plugin folder and instantiates the class named after the file: 10 two-sample tests, 3 two-group
tests, 2 multi-group tests, post-hoc tests, confidence-interval methods, effect-size filters,
multiple-comparison corrections and 18 plot types. Results feed the statistics table and the
matplotlib canvases embedded in the main window.

**Front end.** The main window and every dialog come from upstream's `.ui` files. Qt 6.11 still
ships the classic `Windows` widget style on macOS; the port selects it (Fusion as fallback) with
its standard light palette and keeps the menu bar inside the window, to match the Windows build
that the 109BL lab manual documents. Each plot family restores matplotlib 1.4's defaults (ticks
in, black patch edges, cap size 3, round-number limits) around its own `plot()`.

**macOS integration (new, outside the analysis code).**
- `installLocation.py`: when STAMP runs outside an Applications folder (Downloads, a mounted
  disk image, or macOS's translocated copy, resolved with `SecTranslocateCreateOriginalPathForURL`),
  a native alert offers to move it. The copy goes to `/Applications`, or `~/Applications` when
  the account cannot write there (no password), is checked with `codesign --verify --strict`,
  has its quarantine flag cleared so it does not run translocated, and relaunches; the original
  and the downloaded zip (or the ejected dmg) go to the Trash. A different app that happens to be
  named `STAMP.app` is never replaced (bundle identifier check).
- `updater.py`: loads the bundled `Sparkle.framework` through the Objective-C runtime and starts
  `SPUStandardUpdaterController`. Feed URL, public EdDSA key and schedule live in `Info.plist`
  (check at launch and every 24 h, no silent install). Manual checks: STAMP menu, Help menu, Dock menu.
- `appMenu.py`: About STAMP (the standard macOS About panel) and Check for Updates in the
  application menu. Links go through stable `mimg.io` redirects so the repository can move
  without an app update.
- `macNative.py`: a ~110-line `ctypes` bridge to the Objective-C runtime (`objc_msgSend`) for
  `NSAlert`, `NSBundle`, the About panel and menu icons, avoiding a PyObjC dependency.

## How the port was done

1. **Baseline.** Upstream `088aacd` was committed byte-for-byte as the first commit (tree hash
   equal to upstream's), so every later change is an auditable diff. Six files with classic-Mac
   CR line endings were normalised to LF so Python 3 can parse them.
2. **Python 2 → 3.** A mechanical `2to3` pass, then a manual audit of semantics `2to3` cannot see:
   every `/` whose result is used as an index, count, range bound or pixel size (true division vs
   floor division), `cmp`-style sorts, iterator-returning `map`/`filter`/`zip`/`dict` views,
   `round()` returning `int`, text decoding, and removed scipy aliases (for example
   `scipy.random.random_integers(lo, hi)` → `numpy.random.randint(lo, hi + 1)`, preserving the
   inclusive bound).
3. **PyQt4 → PyQt6.** Old-style `SIGNAL()` connections converted to bound signals, custom
   signals declared with `pyqtSignal`, fully scoped enums, `QtGui`/`QtWidgets` split,
   `QString`/`QVariant` removed, `QSettings` typed reads (`type=float/int/bool`), `QFileDialog`
   tuple returns, `exec_()` → `exec()`. All 34 UI modules regenerated from the `.ui` files with
   `pyuic6` rather than hand-edited; the resource module converted to `bytes` literals.
4. **matplotlib 1.4 → 3.11.** QtAgg backend, removed APIs replaced (`inverse_transformed`,
   `axes_grid`, `set_axis_bgcolor`, `cm.get_cmap`), and the 1.4 look restored per plot family.
5. **Parallel work.** The port was split by ownership (core, GUI, plots per mode) into separate
   git worktrees and branches with disjoint file sets, merged after each passed its tests
   (rules in [PORTING.md](PORTING.md)).

## Verification

The port is checked against two independent references.

- **Parity with the original program.** The unmodified Python 2.7 / PyQt4 STAMP was built in a
  Linux container and run on the same inputs; its outputs are stored in `tests/golden/`.
  `tests/test_golden_parity.py` compares 2,558 scenarios (every test, CI method, correction and
  filter on the upstream examples and the 109BL soil tables). Criterion: every p-value, corrected
  p-value, effect size and CI endpoint within 1e-6 (absolute or relative), every significance
  decision identical (1,686 filter decisions), rows matched by feature name. The remaining
  differences are floating-point noise from scipy 0.19 vs 1.18 (the Student-t quantile used for
  CI endpoints differs in the 8th–9th digit).
- **Accuracy against ground truth.** `tests/accuracy/` recomputes every exposed statistic with
  exact rationals or `mpmath` at 50 digits (the oracle is itself checked against closed forms).
  Criterion: within 1e-12, or a documented, measured bound where the algorithm is approximate
  (log-gamma in Fisher/hypergeometric, Newcombe-Wilson grid search, tabulated studentized range,
  Monte Carlo tests within binomial bounds).
- **Upstream defects.** The accuracy suite found 13 defects that are present in upstream and in
  the Windows build (for example Fisher's two-sided test dropping exactly tied tables, an
  incorrect studentized-range row for df = 2). They are kept for parity with the class's Windows
  build and pinned as strict expected failures in `tests/accuracy/test_acc_defects.py`; the list
  is in [architecture.md](architecture.md).
- **Windows build identity.** The `STAMP.exe` the lab manual installs ships Python bytecode that is
  identical to upstream's `v2.1.3` tag for all 167 modules; the port keeps upstream's later
  author fixes and the v2.1.3 `White.py`, so its behaviour matches what students run.
- **End to end.** The lab manual's CI-5 workflow (load profile and metadata, two samples, two
  groups with the p-value filter, multiple groups with post-hoc, 300 DPI export) is scripted in
  `tests/walkthrough_ci5.py`; on the Skirball demo only Bacteroidetes remains after the filter,
  as the manual states.

Full suite: `uv run pytest -q` (637 passed, 13 expected failures; GUI tests run offscreen).

## Build and release

The release pipeline (branches, versions, GitHub Releases, website sync) is in [RELEASING.md](RELEASING.md).


```
uv run pytest -q                         # test gate
packaging/release.sh --dev               # notarized app + zip, Archive Utility check (~3 min)
STAMP_VERSION=2.1.8 packaging/release.sh # + dmg and pkg (notarized in parallel) + appcast
```

`sign_notarize.sh` builds the bundle with PyInstaller, adds Sparkle (without its XPC services;
STAMP is not sandboxed), signs every Mach-O file inside out with the hardened runtime and a
secure timestamp, notarizes and staples the app, and zips it without AppleDouble entries (which
Archive Utility would write into framework roots and break the seal). `verify_zip.sh` extracts the
zip with Archive Utility, as a browser download would be, and checks the seal, the staple and
Gatekeeper. `make_appcast.sh` signs the zip with the EdDSA key from the keychain and adds it to
the feed. Versions are semantic (`major.minor.patch`); the feed is the only mutable file and every
release zip lives at an immutable versioned URL.
